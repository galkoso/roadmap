# מפת הדרכים של המדור

מערכת Angular במצב כהה (Dark Mode), מקומית לניהול עבודות ומשימות לפי צוותים, בעברית וב־RTL. ציר התאריכים מתקדם משמאל לימין. אין API, חשבונות, שרת נתונים, שירותים בתשלום או מפתחות API.

## גרסאות והתקנה

הגרסאות אומתו בזמן הבנייה ב־12.10.2026 מול npm וטבלת התאימות הרשמית של Angular:

- Node שנבדק: **22.22.3**. Angular 22 דורש ‎`^22.22.3 || ^24.15.0 || >=26.0.0` לפי חבילת הבנייה; מומלץ להשתמש ב־22.22.3.
- pnpm: **10.13.1**.
- Angular / CLI / build / Router: **22.2.2**.
- TypeScript: **6.0.3**, במצב strict ו־strictTemplates.
- RxJS: **7.8.2**; Vitest: **4.1.0**; fake-indexeddb: **6.2.5**; Playwright: **1.64.0**.

```sh
corepack enable
corepack prepare pnpm@10.13.1 --activate
pnpm install --frozen-lockfile
pnpm start
```

פתחו **http://127.0.0.1:4200**. השתמשו באותה כתובת בכל הפעלה: `localhost` ו־`127.0.0.1`, פורטים שונים, ו־HTTP לעומת HTTPS הם מקורות אחסון נפרדים.

## בנייה והרצת הפלט מקומית

```sh
pnpm build
pnpm preview
```

הפלט ב־`dist/roadmap/browser`; שרת הפלט ב־http://127.0.0.1:4200. יש לעצור את שרת הפיתוח לפני הרצת preview באותו פורט. שני השרתים מגישים קבצים בלבד. אין לפתוח את index.html ישירות באמצעות `file://`.

אחרי התקנת החבילות, build והרצה אינם צריכים אינטרנט. האפליקציה לא פונה לשרת חיצוני; כל ה־CSS, קוד ואייקון מקומיים. האייקונים הם טקסט ו־SVG, והגופן הוא Arial / Helvetica מקומי עם fallback לגופן מערכת; אין CDN או טעינת גופנים מרוחקת.

## שימוש

- ״כותרת חדשה״ יוצרת קבוצת משימות תחת צוות קיים, ללא תאריכים או משך. הכותרת מופיעה בשני העמודים גם כשהיא ריקה. הוספת משימה היא פעולה נפרדת: ״משימה חדשה״ יוצרת משימה עצמאית, ו־＋ ליד כותרת יוצר משימה תחתיה. Escape או ביטול סוגרים ללא שינוי.
- נתוני הדוגמה נוצרים רק כאשר אין תכנון שמור, עם תאריכים סביב יום ההפעלה בירושלים.
- כותרת צוות מקפלת את הקבוצה; כותרת עבודה מקפלת רק את מופע העבודה בצוות הזה. Enter ו־Space פועלים על הכפתורים.
- כפתור ⋯ לצד כותרת חדשה פותח שינוי שם; ＋ מוסיף משימה. בכותרות צוות חדשות אין פס זמן. עבודות משותפות קיימות שומרות את ההקרנות לפי צוות ואת עורך העבודה עם הזזת כל המשימות; עבודה ריקה מהסוג הישן מופיעה בצוות הראשון.
- סמל הפח ליד משימה או עבודה מאפשר מחיקה ישירות מהציר, לאחר אישור. מחיקת משימה מסירה רק את קשריה ואינה מזיזה משימות אחרות; מחיקת עבודה מסירה את כל משימותיה בכל הצוותים. Undo משחזר את המחיקה כפעולה אחת.
- לחיצה על משימה פותחת טופס מתחת לציר. השדות נשארים בטיוטה עד ״שמירת השינויים״; ביטול או סגירה משליכים את הטיוטה. כפתור × מחזיר את המקום לציר.
- גוף פס משימה מזיז אותה. הקצה השמאלי משנה את ההתחלה, והימני משנה את הסיום. פס עבודה אפור מזיז את כל משימות העבודה בכל הצוותים; אין לו ידיות שינוי משך.
- בזמן גרירה מוצגים התאריך בפועל, משך ושמות המשימות שהושפעו. Escape או pointercancel מבטלים את כל התצוגה המקדימה. מסד הנתונים אינו נכתב בכל pointermove.
- הזזה ליום שישי או שבת נצמדת ליום ראשון. בטופס, תאריך כזה יוצר שגיאה עם הצעת התאריך הבא, ולא נשמר בחשאי.
- טופס משימה מספק חלופה מלאה לגרירה. בטופס עבודה ניתן להזיז את העבודה כולה לתאריך התחלה חדש.
- גלילה אופקית ימינה ממשיכה אוטומטית לתאריכים עתידיים, וגלילה שמאלה לתאריכים קודמים, בלי צורך בחיצי ניווט. חלון התאריכים המצויר מוגבל בגודלו ומועבר תוך שמירת התאריך באותו מיקום על המסך. תאריכי המשימות אינם משתנים.
- משימה מחוץ לטווח נשארת בתאריכים שלה; כפתור ↗ בשורתה מנווט לתחילתה.
- Undo / Redo באמצעות Ctrl/Cmd+Z ו־Ctrl/Cmd+Shift+Z או Ctrl/Cmd+Y כאשר המיקוד אינו בתוך שדה. היסטוריה עד 50 פעולות בזיכרון בלבד; רענון מאפס אותה. פעולה כוללת את כל שרשרת התזמון שנגרמה ממנה.
- כפתור ״עריכת צוותים״ בסרגל או סמל ✎ ליד שם הצוות פותחים את שינוי שמות הצוותים. ערכו את השם ולחצו ״שמירת שם״ או Enter; השינוי נשמר מקומית.
- תפריט ⋯ בסרגל מנהל צוותים וגיבוי. מחיקת צוות עם משימות דורשת בחירת צוות חלופי; ניתן לבטל. תמיד נשאר צוות אחד לפחות.

## בקלוג וניווט

לפריט בקלוג אפשר להזין ״משך משוער בימי עבודה״ (מספר שלם בין 1 ל־10,000, ראשון–חמישי). המשך ניתן לעריכה מהירה בשורת הפריט או בטופס ומשמש כברירת מחדל בשיבוץ; סיכום הצוות מציג את סך ימי העבודה של פריטי הבקלוג בלבד; אפשר לשנות אותו בעת השיבוץ. החזרת משימה משובצת לבקלוג שומרת את משכה הנוכחי בימי עבודה. השדה `estimatedWorkingDays` נשמר במסמך ובגיבוי כשדה אופציונלי תואם לנתונים קיימים; נתונים ישנים ללא השדה נשארים תקינים ומוצגים כ״משך לא הוגדר״. יצירה חדשה מציעה 5 ימי עבודה הניתנים לעריכה.

בטופס הוספת משימה עצמאית או משימה תחת כותרת אפשר לסמן ״הוספה לבקלוג״. הפריט נשמר ללא תאריכים. כותרות צוות חדשות נשארות גלויות בשני העמודים גם בלי משימות רלוונטיות. עבודות משותפות ישנות שכל משימותיהן בבקלוג אינן מופיעות בציר הזמן; עבודה ישנה ריקה נשארת גלויה כדי לאפשר הוספת משימה ראשונה.

הניווט הקבוע בראש המסך משתמש ב־Angular Router ובנתיבים **`/roadmap`** ו־**`/backlog`**, וכן **`/planning`** לתכנון חודשי. `/` מפנה ל־Roadmap. קישורים, Back/Forward ורענון נתיב ישיר עובדים גם על הפלט הבנוי: שרת הפלט המקומי (`scripts/serve-static.mjs`) מגיש index.html עבור נתיבי היישום, בלי API או מסד מרוחק.

- בבקלוג: ״＋ פריט לבקלוג״ יוצר פריט ללא תאריכים. צוות ועבודה אופציונליים; ״ללא צוות״ ו״פריט עצמאי״ אינם יוצרים ישויות פיקטיביות.
- לחצו על שם הפריט לעריכת כותרת, צוות, עבודה, צבע, סטטוס והערות. החלפת צוות בבורר השורה נשמרת מיד ומעבירה את השורה לקבוצה הנכונה. אפשר לבחור ״ללא צוות״ באופן קבוע.
- הבקלוג מוצג לפי עבודות (צוות → וקטור → משימה); הקבוצות משתמשות בצוותים האמיתיים וכוללות ״ללא צוות״. הקיפול והגלילה נשמרים; החיפוש מסנן לפי שם המשימה.
- כותרות הבקלוג מוצגות כשורות קומפקטיות עם מספר המשימות וסכום ימי העבודה המשוערים שלהן (לא טווח קלנדרי). ＋ מוסיף משימה בהקשר הצוות הנוכחי ו־✎ משנה את שם הכותרת בכל הצוותים. הוספה מוצלחת פותחת את הקבוצה. הקיפול נעשה בנפרד באמצעות כותרת הצוות או הווקטור.
- ״שיבוץ בזמן״ פותח דיאלוג עם תאריך התחלה, משך בימי עבודה וצוות/עבודה אופציונליים. הסיום והמועד החוקי לפי תלויות מוצגים מראש, יחד עם משימות משובצות שיושפעו. ביטול אינו משנה נתונים.
- אישור השיבוץ מעדכן את **אותו ID** למצב scheduled. נשארים בבקלוג; ״הצג בציר הזמן״ פותח את הקבוצות הנחוצות, מנווט לתאריך, גולל לשורה ומדגיש אותה, בלי לאפס זום.
- משימה עצמאית מוצגת תחת כותרת תצוגה ״משימות עצמאיות״; משימה ללא צוות מוצגת בקבוצת תצוגה ״ללא צוות״. הן אינן רשומות עבודה/צוות במסד.
- בתפריט שלוש הנקודות ליד כל משימה בציר הזמן בוחרים ״העברה לבקלוג״. אפשר גם לבחור ״החזרה לבקלוג״ בעריכת משימה מסירה את תאריכי השיבוץ בלבד, לאחר אישור, ומשמרת ID, metadata ותלויות. אם יש צאצאים משובצים, הפעולה חסומה ומציגה את שמותיהם.
- פריט בקלוג אינו משנה טווח עבודה ואינו זז או משובץ אוטומטית כשמזיזים את העבודה או קודמת שלו. שיבוץ עם קודמת ללא תאריכים חסום; אפשר לשבץ אותה קודם או להסיר את התלות במפורש דרך עריכת הפריט.
- שיבוץ, החזרה ומחיקה נשמרים אטומית ונתמכים ב־Undo/Redo. מחיקת פריט בקלוג אינה מוחקת את העבודה הקשורה.
- מעבר בין העמודים משחזר את תקופת ה־Roadmap, זום, קיפול וגלילה ככל האפשר. פתיחה חדשה או רענון עדיין מתחילים על היום, בהתאם לברירת המחדל שנבחרה קודם. טפסים ששונו מציגים אישור לפני מעבר או בקשת רענון; ביטול המעבר שומר את הטיוטה.

## אנשי צוות ואחריות

- כפתור ״אנשי הצוותים״ מופיע בסרגל של Roadmap. אפשר להוסיף שם וצוות קיימים, לשנות שם, להעביר אדם לצוות אחר או להסיר אותו. אלו רשומות תכנון בלבד, ללא חשבונות או הזמנות. שמות נחתכים מרווחים; שמות זהים מותרים ומוצגים עם מזהה מבחין.
- בשורת משימה ובטופס העריכה יש בורר ״אחראי״. כל משימה יכולה להיות ללא אחראי או עם אדם אחד מהצוות שלה. הבורר מציג רק אנשי אותו צוות. ללא צוות הבורר מושבת עם הסבר. שינוי צוות מסיר אחראי שאינו שייך לצוות החדש ומציג הודעה.
- בבורר ״תצוגה״ ב־Roadmap בוחרים ״לפי עבודות״ או ״לפי אנשים״, עם קיפול נפרד לקבוצות האנשים והעבודות. הבקלוג מוצג לפי עבודות. שינוי תצוגה או אחראי אינו משנה תאריכים, תלויות, צבע, סטטוס או הערות.
- בתצוגת אנשים ההיררכיה היא צוות → אדם → משימה. כל אדם מופיע גם בלי משימות, עם ראשי תיבות ומספר משימות בעמוד הנוכחי. שם העבודה מופיע לצד המשימה. בציר הזמן כל משימה שומרת שורה ופס משלה; לכותרת אדם אין פס ואי אפשר להזיז את כל משימותיו יחד.
- ״ללא אחראי״ היא קבוצת משימות בתוך צוות קיים. ״ללא צוות״ היא קבוצה נפרדת למשימות שאין להן צוות, ולכן גם אין להן אחראי. אלו כותרות תצוגה בלבד, ללא רשומות מלאכותיות במסמך.
- העברה או הסרה של אדם דורשות אישור שמציג את מספר המשימות המושפעות בציר הזמן ובבקלוג. המשימות נשארות בצוותיהן וכל שאר הנתונים נשמרים; רק האחריות מתאפסת. הפעולה והעדכון של כל ההפניות נשמרים יחד וניתנים לביטול ב־Undo אחד. אי אפשר למחוק צוות עם אנשים לפני שמעבירים או מסירים אותם במפורש.
- שיבוץ פריט או החזרה לבקלוג שומרים את האחראי כשהוא תקף. ״הצג בציר הזמן״ פותח את קבוצת האדם או העבודה המתאימה לפי התצוגה הנוכחית.
- הגיבוי כולל אנשי צוות, אחראים והעדפות. גיבויים ישנים נטענים ללא אנשים וללא אחראים, ללא שינוי יתר נתוני התכנון. גיבוי חדש עם אדם חסר, צוות חסר או אחריות לצוות אחר נדחה לפני החלפת המסמך. ״נשמר״ מופיע רק לאחר הצלחת עסקת IndexedDB.

## תכנון חודשי — היקף צוותי ובחירת משימות

העמוד `/planning` הוא סביבת תכנון ביניים עם בחירה נוכחית אחת. אין בחירת חודש, חלוקה לחודשים או הגבלת תאריכים. הניווט אליו ובחזרה משמר את טווח וזום ה־Roadmap ואת קיפול וגלילת הבקלוג; רענון ה־Roadmap שומר על ההתנהגות הקיימת של התמקדות ביום הנוכחי.

- בוחרים צוות ומזינים ידנית ״ימי עבודה זמינים לצוות״. נדרשת שמירה מפורשת. שדה ריק אינו אפס; מתקבלים 0 ועד 1,000,000 ימים, בכפולות של חצי יום. הקיבולת אינה מחושבת מלוח שנה.
- ״פירוט לפי חיילים״ מציג את אנשי הצוות הקיימים ואת זמינותם. הפירוט אינו משנה את קיבולת הצוות ואינו משייך משימות לחיילים. מוצגים הסכום שחולק, היתרה שלא חולקה והתרעה על חריגה. בהעברת חייל או הסרתו נמחקת זמינותו מהצוות הישן; היא אינה מועברת לצוות החדש. הקיבולת הידנית ובחירת המשימות נשמרות.
- מימין המשימות שנבחרו, ומשמאל מועמדות מהבקלוג. בבורר ״מקור המשימות״ אפשר להציג משימות של הצוות, משימות ללא צוות או את שתיהן (ברירת המחדל). ״＋ לתכנון״ מסיר משימה רק מרשימת המועמדות בעמוד זה; היא נשארת בבקלוג המקורי ללא שינוי בתאריכים, סטטוס, היקף או אחראי. ״הסרה״ מבטלת את הבחירה בלבד. אפשר לבחור משימה ללא צוות ישירות לתכנון; נשמר קישור לצוות המתכנן בלבד, בלי לשנות את `teamId` של המשימה בבקלוג או ב־Roadmap. המשימה מסומנת במפורש ״ללא צוות״. אחרי בחירה היא אינה מוצעת שוב בצוות אחר, כדי למנוע ספירה כפולה.
- כל צד מקובץ לפי מזהה הווקטור; וקטורים בעלי אותו שם אינם מתאחדים. משימות עצמאיות מקובצות בתצוגה בלבד. הקיפול נשמר בנפרד לכל צוות, צד ומזהה וקטור; מעבר משימה פותח את קבוצת היעד.
- ההיקף מבוסס על `estimatedWorkingDays` למשימות בקלוג ועל משך ימי העבודה בפועל למשימות משובצות, כולל עדכוני משך בציר. זהו מדד העבודה הקיים, לא מודל נפרד של ימי־אדם: אין הכפלה במספר חיילים או אחראים, ואין חישוב לפי הטווח הקלנדרי של הווקטור. משימה ללא הערכה מסומנת ״חסר היקף״; מוצגים הסכום הידוע ומספר החסרים והיתרה מסומנת כלא סופית. אפשר להשלים היקף בטופס העריכה הקיים.
- ״ל־Roadmap״ פותח את אותו טופס שיבוץ של הבקלוג, עם בחירת תאריך, ימי ראשון–חמישי ואימות תלויות. רק אישור שיבוץ משנה את מצב המשימה. נשמרים המזהה, הנתונים והבחירה לתכנון; מוצג ״שובצה ב־Roadmap״ עם קישור לציר. הסרת משימה משובצת מהתכנון אינה משנה את שיבוצה ואינה מחזירה אותה לרשימת המועמדות.
- הבחירה נשמרת כהפניות למזהי משימות במסמך. בחירות רגילות ממשיכות להתעדכן לפי צוות המשימה. לבחירה של משימה ללא צוות נשמר `taskTeamLinks` נפרד עם מזהה המשימה והצוות המתכנן, כך ששינוי שיוך המשימה אינו מעביר את בחירת התכנון. הקישור נשמר גם אחרי שיבוץ, Undo/Redo וגיבוי. אם צוות התכנון נמחק, הבחירה מופיעה באזור ״משימות בתכנון ללא צוות״ עם אפשרות לקשר אותה לתכנון של צוות קיים בלי לשנות את המשימה המקורית. השדה אופציונלי ותואם לגיבויי סכימה 4 קיימים; בחירות ישנות ללא קישור מפורש שומרות על התנהגותן. מחיקת משימה או צוות מנקה את ההפניות דרך פעולת העריכה הקיימת. שינוי שם שומר על הקיבולת והבחירה באמצעות מזהים קבועים.
- קיבולות, פירוט ובחירה משתתפים ב־Undo/Redo באמצעות הקיצורים הקיימים. הם נשמרים יחד עם העדפות הצוות הפעיל והקיפול בעסקת IndexedDB, ונכללים בגיבויי JSON בסכימה 4. גיבויי 1–3 מיובאים עם בחירה ריקה וקיבולת שלא הוזנה. הפניות כפולות/חסרות, ערכים שליליים או לא תקינים ופירוט לחייל בצוות אחר נדחים לפני החלפת נתונים. בכשל שמירה החיווי מציג שינויים בזיכרון בלבד ומאפשר ייצוא וניסיון חוזר.

## כללי התזמון

- ימי העבודה: ראשון עד חמישי. חגים **אינם מוחרגים**. שישי ושבת נשארים על ציר התאריכים הרציף ומודגשים ברקע בתצוגות מפורטות.
- תאריכים נשמרים כ־`YYYY-MM-DD`, ללא שעה. מנוע התאריכים משתמש בימי לוח UTC, ולא במרווחי מילישניות באזור זמן מקומי; שעון קיץ אינו מזיז תאריכים. ״היום״ ונתוני הדוגמה משתמשים באזור הזמן Asia/Jerusalem.
- הסיום כולל; משימה שמתחילה ומסתיימת ביום עבודה אחד נמשכת יום אחד, עם פס שניתן לבחור.
- כל עבודה או כותרת נשמרת פעם אחת. לכותרת חדשה יש צוות יחיד והיא אינה משימה; עבודות משותפות ישנות נשמרות ללא בעלות צוות יחידה. ההופעות בצוותים הן הקרנות; הטווח האפור מחושב רק ממשימות משובצות בכל הצוותים. משימה יכולה להיות ללא צוות וללא עבודה, או להשתייך לצוות ולעבודה קיימים.
- קשרים הם **סיום–להתחלה בלבד ובתוך אותה עבודה**, גם בין צוותים שונים. המרווח הוא מספר שלם לא שלילי של ימי עבודה פנויים: `addWorkingDays(predecessorEnd, 1 + lagWorkingDays)`.
- בריבוי קודמות לוקחים את המועד המאוחר ביותר. שינוי משימה מחשב רק צאצאים בסדר טופולוגי, עם שמירת משך כל צאצא. אין תלות בסדר השורות.
- דחייה ידנית מעדכנת את מרווחי הקשרים הנכנסים. הזזה מוקדמת מהמגבלה הנוכחית נצמדת למועד החוקי ומוצגת בחיווי. ניתן לשנות את המרווח עצמו בטופס כדי להקטין אותו.
- יצירת קשר חדש משמרת מיקום שכבר חוקי ומחשבת מרווח מתאים. אחרת מזיזה את המשימה ואת צאצאיה. הסרת קשר או מחיקת משימה אינן דוחסות תאריכים.
- הזזת עבודה מעבירה כל משימה באותו הפרש של ימי עבודה, ומשמרת משכים, מרווחים, צבע, צוות וסטטוס. עבודות אחרות אינן מושפעות.
- סטטוסים נערכים ידנית; ״הושלמה״ אינה נועלת את התזמון. **צבע נבחר ידנית ואינו נגזר מצוות או מסטטוס**.
- הערות הן **טקסט רגיל**, ללא HTML או עורך עשיר. תוכן מיובא אינו מורץ.

## שמירה וגיבוי

מסמך התכנון, הרוויזיה והעדפות התצוגה נשמרים יחד בעסקת IndexedDB אחת. חיווי ״נשמר״ מוצג רק אחרי סיום העסקה. נשמרים גם זום וקיפול קבוצות. בפתיחה או ברענון הציר תמיד מתמרכז על היום, בהתאם להתנהגות ברירת המחדל; תקופה וגלילה קודמות אינן משוחזרות לתצוגה. בכל מעבר בין שבועות, חודשים ורבעונים חוזרים להיום. הניווט לתאריכים קודמים ועתידיים נעשה בגלילה הרציפה של הציר. בדיקת רוויזיה נעשית בתוך עסקת כתיבה כדי למנוע דריסה מלשונית ישנה.

בכשל כתיבה, השינויים נשארים בזיכרון. החיווי מתחלף לשגיאה וניתן לייצא אותם. בכשל זמני ניתן לנסות שוב. כשיש רוויזיה חדשה מלשונית אחרת, יש לייצא את המצב בזיכרון לפי הצורך ולבחור ״טעינת הגרסה המקומית החדשה״ לפני המשך שמירה; אין מיזוג אוטומטי.

**הנתונים מקומיים לדפדפן, לפרופיל ולכתובת היישום. מחיקת נתוני דפדפן או שינוי כתובת אינם גיבוי.** ניתן לבקש persistent storage בתפריט הגיבוי. הדפדפן עשוי לסרב, ואישור אינו מבטיח חסינות ממחיקה. שימוש בחלון פרטי עשוי להיות זמני.

ייצוא מוריד `roadmap-backup-YYYY-MM-DD.json` עם schemaVersion, זמן ייצוא, מסמך מלא והעדפות. שמרו את הקובץ מחוץ לאחסון הדפדפן.

ייבוא: בחירת JSON → אימות → תקציר צוותים/עבודות/משימות → אפשרות לייצא קודם → אישור מפורש → החלפה אטומית. המסמך והייצוא משתמשים בסכימה **4**. מסמכים וגיבויים מסכימות **1, 2 ו־3** עוברים מיגרציה בזיכרון: משימות מסכימה 1 הופכות ל־scheduled; בסכימות 1 ו־2 נוספים אוסף אנשים ריק ואחראי null; בכל הגרסאות הישנות נוסף מצב תכנון ריק עם קיבולות שלא הוזנו, בלי שינוי IDs, תאריכים, צבעים, סטטוסים או תלויות. הנתונים נשארים באותו IndexedDB ובאותה כתובת. המיגרציה נכתבת בעסקה אטומית ורק אחרי אימות. גרסאות אחרות נדחות. נתונים ישנים לא תקינים אינם נמחקים, אינם מקבלים תאריכי דמה ואינם מוחלפים בדוגמה; הטעינה מציגה שגיאה וניתן לייצא את המקור באמצעות ״ייצוא הנתונים המקוריים לבדיקה״. קובץ recovery הוא חומר לבדיקה, ואינו גיבוי תקין בהכרח. קובץ שגוי או עסקה שנכשלה אינם משנים את התכנון הקיים. יש הגבלה של 10MB לקובץ ו־10,000 רשומות לכל אוסף.

## מבנה הפרויקט

- `src/app/core/model.ts` — Task הוא איחוד של ScheduledTask (תאריכים חובה) ו־BacklogTask (ללא תאריכים), עם planningState נפרד מסטטוס הביצוע, שיוכים nullable ומקור אמת אחד ב־document.tasks.
- `dates.ts` — פונקציות date-only ולוח ראשון–חמישי, TypeScript טהור.
- `scheduler.ts` — גרף, זיהוי מעגלים, הזזה, שינוי משך והתפשטות לצאצאים; TypeScript טהור, ללא Angular/DOM.
- `validation.ts` — אימות מסמכים וגיבויים, מזהים, references, סוגים, צבעים, תאריכים, חוקיות תלויות וסכימה.
- `storage.ts` — IndexedDB, כתיבה אטומית ובדיקת רוויזיה; ללא Angular.
- `store.ts` — Signals ו־computed, מסמך מאושר מול preview, תור כתיבה, חיוויים ו־Undo/Redo.
- `ui/timeline.component.ts` — הקרנות צוות–עבודה, קיפול, מיפוי יחיד של תאריך לפיקסל, פסי זמן ו־SVG לתלויות גלויות של המשימה הנבחרת. שורות מזוהות לפי IDs; אין החלפת DOM כולו בזמן גרירה.
- `ui/task-editor.component.ts` — טיוטת טופס נפרדת, תלויות ומרווחים, עריכה/יצירה/מחיקה.
- `app.component.ts` ו־`app.routes.ts` — מעטפת ניווט קבועה, Router והגנה על טפסים שלא נשמרו.
- `ui/roadmap-page.component.*` — ציר הזמן, עבודות, צוותים וגיבוי.
- `ui/backlog-page.component.*` — קבוצות לפי עבודות, חיפוש ועריכת משימות.
- `ui/backlog-task-dialog.component.*` — טופס עריכה ושיבוץ משותף לבקלוג ולתכנון החודשי, עם אותו מנוע תזמון.
- `core/planning.ts` ו־`ui/planning-page.component.*` — הפניות לבחירת משימות, קיבולות, חישוב היקף וקיבוץ לפי וקטור, ותצוגת התכנון.
- `ui/create-work-dialog.component.ts` — יצירה ועריכה של כותרות צוות ללא תאריכים; משימות נוצרות בנפרד.

אין ספריית Gantt. גודל חודש מחושב לפי מספר ימי הלוח האמיתי ומאותו מיפוי שמשמש לפסים. כותרת התאריכים sticky בגלילה אנכית, ועמודת השמות sticky מימין בגלילה אופקית. קווי תלות נוצרים רק לשורות שקיימות וגלויות. הקיפול מצמצם רינדור; אין וירטואליזציה בגרסה זו.

## בדיקות

```sh
pnpm test
pnpm exec playwright install chromium
pnpm build
pnpm test:e2e
# כאשר שרת הפיתוח כבר פעיל ב־4200, בדיקת production בפורט נפרד:
ROADMAP_TEST_PORT=4201 pnpm test:e2e
```

בדיקות הדפדפן רצות על **פלט production** דרך שרת סטטי שהן מפעילות ועוצרות בעצמן; יש לפנות את פורט 4200. דוח HTML ב־`playwright-report/index.html`, traces בכשל וצילומי המסך ב־`test-results/roadmap-desktop.png` ו־`test-results/backlog-desktop.png`. כאשר שרת קיים בפורט הבדיקה, Playwright רשאי להשתמש בו; השתמשו בפורט נפרד כדי לאמת בוודאות את הפלט הבנוי. בדיקות יחידה משתמשות ב־fake-indexeddb ואינן צריכות דפדפן. `pnpm test:watch` לפיתוח בדיקות.

מקורות: [תאימות Angular](https://angular.dev/reference/versions), [Signals](https://angular.dev/guide/signals), [Standalone components](https://angular.dev/guide/components), [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), [מדיניות שמירה ומחיקת אחסון](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).
